# Rescue 2026-11-12 — freeze the zoo, fix the books

## What happened

The repo ran 27 paper-trading strategies (S1–S32). **All 27 were BLOCKED from
live money by criterion C5** (graduation report, 2026-11-12): "cash/position
evidence incomplete, mismatched, or changed since audit; reconcile before
graduation." A review (2026-11-12) found the block was partly mechanical
(parseable) and partly genuine (uncertifiable history), and that the
headline rankings were contradicted by the strategies' own backtest files
(e.g. S29 "ranked #1, Sharpe 5.04" actually lost 31.55% per its own NAV CSV).
The rescue freezes the zoo to the 6 strategies with honest evidence, fixes
the mechanical C5 causes, and restarts the three uncertifiable books from
zero. Nothing was deleted: everything removed from the live tree is in
`_archive/` with its original file name.

## What was done

### 1. Quarantined the NAV fabricator
- `reconcile_all_transactions.py` → `_archive/reconcile_all_transactions.py`
  (see `_archive/README_QUARANTINE.md`). It overwrote portfolio JSONs with NAV
  from watchdog history, hardcoded NAVs, invented initial-deposit rows, and
  stamped `[TRUE_PROFIT_VERIFIED]`. It was dead code (not in
  `STRATEGY_SCRIPTS`, not run by the pipeline) and is forbidden by
  `ACCOUNTING_REVIEW_FOLLOWUP.md`. Nothing imports it.

### 2. Mechanical C5 fix — ledger normalization + reconciler adapters
- `normalize_ledgers.py` (repo root; keep as evidence) normalized all 28
  ledgers, idempotently (1,146 changes on the first run, 0 on the second).
  Backups of the originals: `_archive/ledger_backups_2026-11-12/`.
  - Rejoined rows split by unescaped `|` in order notes (note cells joined
    with ` / `).
  - Rebuilt initial-funding rows in the Golden ledgers (S19–S31) so the
    200,000 funding parses (amount moved into the amount column, Order Type
    "Market", Status "FILLED", Note "Initial capital funding"). S31's funding
    row needed a manual fix after the script rejoined it as a note-pipe row.
  - Flipped negative DEPOSIT signs to positive in S4, S5, S6 (5 rows each),
    S9, S10, S11, S16 (4 rows each).
  - Moved S1's stray BONDIA INTEREST row (was above the header) into the
    table in date order.
  - No transactions were invented; only values already recorded were moved,
    re-joined, or sign-corrected. Each change is logged by the script.
- `reconcile_strategy_navs.py` gained adapters (see its comments):
  - `BUY_USD`/`SELL_USD` → BUY/SELL; `BUY_<ticker>`/`SELL_<ticker>` → BUY/SELL.
  - `SETTLE_*` → SELL, cash-only (no position change). Consequence: S10/S11/
    S16 ledgers still show the paired position as open, because SETTLE is
    their only exit. That is a known limitation, not a fix.
  - `EXIT_SHORT`/`EXIT_LONG` → SELL (S11 close-outs; amount column is
    positive cash-in and the position is reduced).
  - `REBALANCE` → no-op with a warning, not an error.
  - Rows with more cells than the header are defensively rejoined (extras
    merged into the note).
  - A FILLED row whose note says "execution failed" is counted as executed
    (status is FILLED) but flagged with a warning. Evidence: S2's two META
    rows (BUY −10,436.46, SELL +13,306.22, net +2,869.76) reconcile the
    portfolio cash to exactly 0.00 when counted — the portfolio reflects
    them, so the note is treated as stale (likely a retried order). Verify
    against a broker statement if in doubt.
  - Price lookup by substring match (handles "Price (MXN)" in S31).
  - `CASH_TOLERANCE = 5.00`: ledger prices are printed to 4 decimals, so
    qty × price rounding accumulates ~0.1–2.5 over hundreds of rows on
    six-figure trades (observed S12 −0.14, S23 −2.23, S24 −2.14). A gap below
    5.00 is display rounding, not a real difference. The smallest genuine
    residual after this fix is S25 at 104.01.
  - `USDMXN` added to `NON_SECURITIES` (S13/S14/S15 carry an FX row).
  - Currency-specific balances moved from errors to warnings: positions are
    verified, cash is explicitly NOT single-currency verified for
    multi-currency books (S13/S14/S15); `cash_difference` stays None for them.
- `tests/test_accounting_review.py`: `test_malformed_and_unknown_ledger_rows_cannot_verify`
  updated honestly — `BUY_USD` replaced with `SPLIT` (still unknown) because
  `BUY_USD` is now supported by design; unpack changed to the 5-tuple.
  Assertion (2 errors) unchanged.
